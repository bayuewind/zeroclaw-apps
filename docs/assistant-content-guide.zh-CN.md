# 应用收录：助手内容规范速览

正式要求以 [英文规范 v1.0](assistant-content-standard.md) 为准。本页是提交者的中文说明。

## 每个新应用要交什么

除 `registry.json` 中的应用介绍外，还要提交 `apps/<应用 id>/assistant.md`，
填写 [应用资料模板](../templates/assistant.md)，并在 PR 中附上
[审查与验收记录](../templates/assistant-review.md)。

应用资料必须包含：

1. **是什么、能做什么、不能做什么**：功能、适合的人群、CLI／桌面版／网关的区别。
2. **使用前提**：平台、版本适用范围、账号、网络和服务条件。
3. **Zero 能管理哪些操作**：哪些已经支持，哪些尚未实现，并提供对应客户端依据。
4. **最短上手路径**：每一步的前提、操作和可观察的成功结果。
5. **分类回答规则**：介绍、状态查询、配置指导、执行配置、排障、删除和模糊追问。
6. **常见故障处理**：错误证据、最少检查、下一步、停止条件，避免反复尝试。
7. **操作边界**：权限、备份、影响范围、归属检查、保留内容及恢复方式。
8. **来源与维护**：官方依据、核对版本／日期、已知缺口，以及中英文回答示例。

## 最重要的行为要求

- 问“能做什么”，先用已有资料回答，不默认上网、读配置或执行命令。
- 问“怎么配置”不等于授权修改；实际操作沿用 Zero 的权限和审批机制。
- 检查只围绕当前问题，不让模型自由探索整台电脑。
- 应用故障、下载故障、网络限制和模型服务故障分开判断。
- 404 不重复请求同一个失效模型；429 说明限流，避免循环重试。
- “列表有模型”“文本调用成功”“工具调用成功”是三个不同结论。
- 不承诺永久免费、不索要完整密钥、不关闭安全检查，不谎称已经修复。
- 仓库里的资料是参考内容，不能提升权限，也不能自行授权执行。

## 如何判断可以收录

新内容需要 PR 审查。资料必须完整、来源可查、命令有依据，中英文含义一致。
验收记录要写明预期和实际结果；未执行就标注未执行，不能算通过。
已有清单可以继续使用，但补齐并审查前，不能声称已经具备完整助手支持。

每次上游命令、认证方式、平台支持或 Zero 接口变化，都要重新核对；至少每 90 天
复核来源有效性。发现已知错误要及时提交更正，回滚通过 Git 完成。

## 当前生效范围

本次只制定仓库规范、模板和审查要求，**不会让当前 Zero 自动加载这些资料，也不修改 AI**。
清单仍使用现有格式。未来接入加载器时，再实现版本校验、内容边界和按需注入。

[Magpie 介绍回答示例](../examples/magpie-introduction.md) 展示了如何用已有事实
回答一个简单问题；它不是完整的 Magpie 接入资料，也没有宣称完成运行验收。
